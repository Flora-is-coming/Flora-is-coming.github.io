队列

队列queue

C++中，queue 是标准模板库（STL）中提供的一个容器，用于实现队列。queue 是一个先进先出（FIFO，First-In-First-Out）数据结构，即最早进入队列的元素最早被移除。

C++ 中 queue 的常用操作：

  1. **push()**：将元素添加到队列的尾部（入队）。
  2. **pop()**：移除队列头部的元素（出队）。
  3. **front()**：访问队列的第一个元素，但不移除它。
  4. **back()**：访问队列的最后一个元素。
  5. **empty()**：判断队列是否为空。
  6. **size()**：返回队列中元素的数量。

常见应用：

C++ 的 queue 非常适合用于任务调度、广度优先搜索（BFS）、缓存系统等需要先进先出的场景。

优先队列priority_queue

priority_queue 是 C++ 标准模板库（STL）中的一个容器适配器，用于实现优先队列。与普通的队列（queue）不同，优先队列在插入元素时会自动根据元素的优先级进行排序，保证每次取出的元素都是优先级最高的（在最大堆情况下）或优先级最低的（在最小堆情况下）。

priority_queue 的特点

  • 默认是最大堆：priority_queue 默认是实现为最大堆的数据结构，也就是说，优先级值较大的元素会被放在堆顶，优先出队。
  • 基于堆实现：priority_queue 的底层实现是使用了 堆（heap） 数据结构（通常是二叉堆），插入和删除操作的时间复杂度是 **O(log n)**。
  • 自动排序：当元素插入 priority_queue 时，它会自动按照优先级进行排序，保证最高优先级的元素在堆顶。

主要功能和接口

priority_queue 是一个容器适配器，提供了一些基本操作来管理元素：

  1. **push()**：向优先队列中添加新元素。
  2. **pop()**：移除优先队列中优先级最高的元素（即堆顶元素）。
  3. **top()**：访问优先队列中优先级最高的元素，但不移除它。
  4. **empty()**：判断优先队列是否为空。
  5. **size()**：返回优先队列中元素的个数。

默认行为：最大堆

默认情况下，priority_queue 是基于最大堆实现的，即优先级值较大的元素会排在堆顶。也就是说，优先队列中的元素是按从大到小排序的。

总结

  • priority_queue 是 C++ 中的一个容器适配器，用于实现优先队列，默认行为是基于最大堆实现的。
  • 可以通过 greater<T> 或自定义比较函数来实现最小堆或自定义排序。
  • priority_queue 在插入和删除操作上具有对数时间复杂度 O(log⁡n)O(\log n)O(logn)，非常适合用于优先级管理任务。

动态数组vector

通过这个头文件可以调用C++ 标准库中的一个非常常用的容器，类似于动态数组。

动态大小：不像普通数组大小固定，vector 可以根据需要动态增长或缩小。

连续内存分配：vector 使用连续的内存块来存储元素，因此支持快速的随机访问，和普通数组一样。

自动管理内存：vector 会自动处理内存分配和释放，因此用户不需要手动管理内存。

灵活操作：vector 支持在容器的任意位置插入和删除元素，尽管这些操作可能比随机访问慢一些。

哈希表的实现

map

#include < map >

基于红黑树实现（有序二叉搜索树）。它保证键值对按顺序存储，查找、插入、删除操作的时间复杂度为 O(log⁡n)，相对较慢，但更稳定。

存储有序，元素按照键的顺序进行排列。遍历时，按键的字典顺序输出

适用于

  1. 需要按键的顺序遍历时（如范围查询）
  2. 需要有序存储或有序遍历的场景。

unordered_map

#include < unordered_map >

基于哈希表实现。使用哈希函数将键值映射到存储位置，查找、插入、删除操作的平均时间复杂度为 O(1)。但是受哈希冲突时，极不稳定

存储无序，元素的顺序与插入顺序、键的值无关，遍历时的输出顺序是不可预测的。

适用于

  1. 快速查找、插入和删除，且不在乎键的顺序
  2. 适用于大数据量的情况，因为其平均查找效率很高

树

基本术语

• 结点——表示树中的元素，包括数据项及若干指向其子树的分支

 • 结点的度——结点的儿子结点个数

​ • 树的度——一棵树中最大的结点度数

特殊的结点：

• 叶结点——度为0的结点

• 分枝结点——度不为0的结点

结点的高度——从该结点到各叶结点的最长路径长度

• 树的高度——树的根节点到树中最深的叶子节点的最长路径上的边的数量。

• 结点的深度，经过一根，度加一，根结点度为1。

• 有序树——为树的每一组兄弟结点定义一个从左到右的次序

  • 左兄弟右儿子

前序后序中序的定义：

中序遍历的规则是：左子树 -> 根结点 -> 右子树。

那么在遍历到一个根节点的左子树时，这个左子树同样也有左子树，从而要将左子树的左子树遍历完，再返回最初左子树的根节点。

二叉树：特殊的树

二叉树（Binary Tree）是树的一种特例。每个结点最多只能有两个子结点（通常称为左子结点和右子结点）。

二叉树：结点个数和高度的关系

它告诉我们在一棵二叉树中，叶子结点的数量和度为 2 的结点数量之间的关系是：

二叉树是对这种抽象的具体实现，可以有不同的存储方式。

哈夫曼树：特殊的二叉树

哈夫曼树是通过一组权值构造的带权路径长度最小的二叉树

术语

线索标志位：为了区分一个结点的指针是指向其儿子结点的指针，还是指向其前驱或后继结点的线索,在每个结点中增 加的2个位—LeftThread、RightThread分别称为左、右线索 标志位。

二叉搜索树的定义

用二叉树来存储有序集，每一个结点存储一个元素

满足要求：存储于每个结点中的元素x大于其左子树中任一结点 中所存储的元素，小于其右子树中任一结点中所存储的元素。

AVL树：特殊的二叉搜索树

定义

在普通的二叉搜索树（BST）中，树的高度不受控制。如果插入的节点恰好按照升序或降序排列，BST 可能退化成一个链表，导致树的高度为 O(N)，进而让插入、删除、查找等操作的最坏时间复杂度变成 O(N)。

AVL树特殊就特殊在，插入和删除的时候不是一味的插、删，而是在插、删完会旋转，使得树的高度满足上面推导的和结点有关的公式

AVL树的插入（insert）和删除（delete）操作在执行之后，会通过自平衡的机制，保证树的高度是 O(log N) 的，从而让这些操作的时间复杂度在最坏情况下也保持在 O(log N)。

平衡因子的定义

对于任意一个节点 N，其平衡因子的定义为：

  • 如果平衡因子的值为 -1、0、或 1，则该节点被认为是平衡的。
  • 如果平衡因子的值超出这个范围（即小于 -1 或大于 1），则该节点被认为是不平衡的，需要通过旋转操作来重新恢复平衡。

旋转操作：自平衡机制

左单旋：

当某个节点的右子树过高（平衡因子为 -2），而该右子树的右子节点的高度比其左子节点高时（即右子树的平衡因子为 -1 或 0），就需要进行左单旋。

实例

**节点 50**：左子树高度 1（节点 55），右子树高度 2（节点 60），平衡因子 = 1 - 2 = -1

**节点 40**：左子树高度 1，右子树高度 3（节点 50），平衡因子 = 1 - 3 = -2（失衡！）

**节点 30**：左子树高度 2，右子树高度 4（节点 40），平衡因子 = 2 - 4 = -2（失衡！）

于是：

==选择失衡节点 30，其右子节点 40 为新根。==

将节点 30 成为新根的左子节点，同时将 40 的左子树（节点 35）变为 30 的右子树。
